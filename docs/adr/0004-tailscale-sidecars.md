# Serve each hostname from its own Tailscale node

Supersedes [ADR-0002](0002-tailscale-application-ports.md).

Tailscale access runs one `tailscale/tailscale` container per routed hostname inside the Edge Compose project (`compose.tailscale.yaml`, profiles `ts-<name>`). Each node enrolls with one reusable tagged auth key under the hostname's own name (`litellm`, `langfuse`, `s3`, `rustfs`, `backplane`, `grafana`, and the console as `PE_ROOT_HOST`, default `platform`), obtains its certificate from Tailscale, and proxies `https://<name>.<tailnet>.ts.net` to `pe-edge:80` over the Platform Network with the original Host. Edge serves those hosts on its HTTP listener only when the overlay is active and marks the upstream scheme HTTPS for requests from the Platform Network's dynamic range, where the nodes live. Bootstrap `--tailscale` starts the selected nodes, records `PE_TAILNET_DOMAIN` once after enrollment, and probes every origin from the host.

Why not the alternatives from the plan: (B) one node with per-port Serve keeps `https://platform.<tailnet>:8443` URLs, so ports leak into login redirects, presigned S3 links and API clients, the problem ADR-0001 solved for the public domain. (C) host `tailscale serve` per port needs `sudo`, mutates the host daemon from a repository script, and inherits the same port table; that design also had to trust the Docker bridge gateway as an ingress peer to recover client addresses.

Consequences. Seven userspace nodes cost about 60 MB each and one machine entry per hostname in the admin console; `PE_TS_APPS` drops the nodes of absent stacks. The auth key is a secret in `.env`; tagged nodes have no key expiry, so the key's expiry only limits new enrollments, and rotating it is a `.env` edit before the next enrollment. Node identity lives in one external volume per node; deleting it re-enrolls under a suffixed name until the stale machine is removed. All nodes form one authorization domain: a client allowed to reach any node can reach every Tailnet host through it, because Tailscale Serve forwards the client's Host and Edge routes by Host. Tailnet policy therefore grants the tag as a whole, and application login stays the per-application boundary. Edge trusts no forwarded header, so applications see the node's Platform Network address, not the tailnet client; Tailscale identity headers pass through unverified and must not be trusted behind Edge. Sibling browser origins move to the Tailnet Origins through the bundle keys; public-domain routes remain for standalone and public access.
