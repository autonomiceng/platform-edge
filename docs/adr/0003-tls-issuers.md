# The certificate issuer is a setting independent of the access mode

Status: accepted (2026-09-23).

Edge takes its HTTPS certificates from one of three sources per installation, selected by `PE_TLS_ISSUER`: its internal CA (`internal`), an ACME directory (`acme`: Let's Encrypt by default, or a private directory with an optional trust file and external account binding), or operator certificate and key files (`files`). The access mode still decides the listeners, redirects and HSTS; the issuer decides only where the certificates come from. Local mode allows `internal` and `files`, public mode allows `acme` and `files`, and proxy mode has no HTTPS listener and ignores the setting.

Corporate installations either run a private ACME CA (step-ca, an ACME-enabled corporate CA) or hand out certificates from their PKI. Tying certificates to the access mode forced them into the internal CA or into terminating TLS in another gateway, which loses the single-ingress guarantee and the certificate expiry metric. Caddy refuses empty `trusted_roots` and `eab` arguments and applies snippet defaults only to unset variables, so each optional ACME input is a Compose overlay that mounts or declares it and names its snippet (`compose.acme-ca-root.yaml`, `compose.acme-eab.yaml`); `compose.files.yaml` mounts `PE_TLS_DIR` read-only without creating it. Bootstrap selects the overlays and validates the inputs before Compose runs: an `https` directory URL, both halves of the account binding, a certificate whose subject alternative names cover every configured hostname, and files that Caddy's uid 0 can read without `CAP_DAC_OVERRIDE`.

Rejected: a custom Caddy build with a DNS provider module for DNS-01 wildcard issuance, which would replace the validated image pin with one build per provider (deferred; public ACME therefore needs TCP 80 and 443 reachable for every name); making proxy mode the only path for non-ACME certificates; and a default bind directory in `compose.yaml`, which Docker would create as root when missing.

Consequences: file certificates are renewed by the operator's PKI and applied with `caddy reload`; Edge does not watch the directory, and those files are outside the Checkpoint volumes. The readiness probe trusts `PE_TLS_CA` or `PE_ACME_CA_ROOT` when given and the system store otherwise. Route Files declare each hostname once through the `site` snippet, so the issuer is applied in one place. Sibling stacks mirror the same settings under their own prefixes.
